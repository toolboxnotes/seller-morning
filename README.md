# SellerMorning — Amazon Seller Central 도우미 (로컬 RPA)

현재 버전: **v1.2.0** (버전 번호 규칙·기록은 맨 아래 ‘버전 기록’)

## 다운로드

**[최신 버전 다운로드 (SellerMorning.zip)](https://github.com/toolboxnotes/seller-morning/releases/latest/download/SellerMorning.zip)** — 링크는 항상 최신 버전 파일입니다. 특정 버전이 필요하면 [Releases](https://github.com/toolboxnotes/seller-morning/releases)에서 `SellerMorning_v버전_날짜.zip`을 받습니다. 압축을 푼 뒤 아래 순서로 설치합니다.

## 처음 설치 · 실행(Windows / Mac)

| | Windows 10·11 | macOS |
|---|---|---|
| 처음 한 번 | `setup_windows.bat` 더블클릭 | 터미널에서 `bash setup_mac.command` (또는 Finder에서 우클릭 → 열기) |
| 화면 프로그램 | `start_gui.bat` (또는 바탕화면 ‘SellerMorning’) | `start_gui.command` (또는 바탕화면 ‘SellerMorning.command’) |
| 콘솔 메뉴 | `start.bat` | `start.command` |
| 매일 자동 실행 | 작업 스케줄러(`daily_run.bat`) | launchd(`daily_run.command`, 잠자기였으면 깨어난 뒤 실행) |
| 설정·로그인·비밀값 | `%LOCALAPPDATA%\AmazonAIProject`, 비밀값은 Windows 계정 암호화 | `~/Library/Application Support/AmazonAIProject`, 비밀값은 **키체인** |
| 알림 | Windows 알림 | 알림 센터 |

처음 설치가 하는 일: Python 3.9+·Chrome 확인 → 패키지 설치(Mac은 OneDrive 밖 전용 환경 `~/Library/Application Support/AmazonAIProject/venv`)
→ 바탕화면 바로가기 → Seller Central 로그인(브라우저에서 직접) → 화면 프로그램 실행.
- Mac에서 OneDrive로 받은 `.command`는 실행 권한이 없을 수 있어 처음에는 `bash setup_mac.command`로 실행하세요(이후 바탕화면 바로가기는 그대로 동작).
- Mac Python은 python.org 설치본을 권장(Homebrew Python이면 `brew install python-tk` 필요).
- 컴퓨터마다 로그인·API 설정을 따로 합니다(다른 컴퓨터의 암호화된 값은 풀 수 없음). Mac에서는 ⚙ 설정에서 SP-API 값을 다시 입력하세요.
- **같은 OneDrive 폴더를 Windows와 Mac이 함께 쓰면 매일 자동 실행은 한 컴퓨터에서만** 예약하세요(같은 시간에 둘 다 돌면 reports 파일이 겹침).

## 일상 사용: 기능 메뉴

`start.bat`을 더블클릭하거나, 프로젝트 폴더에서 다음을 실행합니다.

```bash
python app\main.py
```

모든 기능이 번호로 표시됩니다. 번호를 입력하고 Enter를 누르면 실행되고, 0을 입력하면 종료합니다.
처음 사용할 때는 먼저 “Seller Central 로그인”을 선택하세요. “개발 중”으로 표시된 기능은 아직 구현되지 않았습니다.

새 기능 추가: `main.py`에 함수를 하나 작성하고 `FEATURES` 목록에 추가하면 메뉴에 나타납니다.
클릭, 스크롤, 페이지 이동은 모두 `human.py`의 함수를 사용하세요. 동작 간격이 매번 2~5초(밀리초 단위) 무작위로 정해지고, 마우스가 곡선으로 움직입니다.

## 계정 상태

메뉴에서 “계정 상태”를 선택합니다. Account Health 페이지를 한 번 둘러보며 계정 상태 점수,
고객 서비스 / 배송 지표, 정책 준수 항목별 건수를 읽고, 지난번 결과와 비교한 뒤 Excel 보고서를 엽니다.

보고서는 `reports/account_health/`에 저장됩니다.
- `account_health_날짜_시간.xlsx`: 일일 보고서
  - “오늘 보고서”: 점수, 주의가 필요한 사항, 성과 지표, 정책 준수, 알려진 미해결 이슈 수
  - “새 이슈”: 이번에 새로 발견된 이슈만 표시(ASIN, SKU, 상품명, 사유, 날짜, 상태)
  - “영향 받는 상품”: 이번에 처음 수집한 상품 정보만 표시(제목, 브랜드, 가격, 평점, 리뷰 수, 구매 상태, 판매 순위)
  - “기록”: 확인할 때마다 한 줄씩, 점수 추이 차트 포함
- `issue_registry.xlsx`: 이슈 대장. 모든 이슈와 상품 정보를 한 번씩만 기록합니다.
  - “이슈 대장”: 이슈별 상태(미해결 / 사라짐), 최초 발견, 마지막 확인, 사라진 시간
  - “상품 정보”: 영향 받는 ASIN별 기본 정보와 미해결 이슈 수
- `account_health_날짜_시간.png` / `_page.txt`: 계정 상태 페이지 스크린샷과 원문 텍스트
- `account_health_날짜_시간_<분류>.png` / `_page.txt`: 이슈 분류 페이지의 스크린샷과 원문 텍스트(들어가 본 경우에만 생성)
- `history.json`, `issue_registry.json`: 프로그램이 사용하는 데이터이므로 직접 수정하지 마세요.

### 이슈는 한 번만 수집

매일 실행할 때 어떤 분류의 이슈 건수가 대장과 같으면 다시 들어가지 않고, 상품도 다시 조회하지 않습니다.
건수가 바뀐 경우에만 들어가서 새 이슈만 대장에 추가하고, 목록에서 없어진 이슈는 “사라짐”으로 표시합니다.
ASIN별 상품 정보도 한 번만 수집합니다.

## 전체 상품 재고 / FBA 재고

두 개의 별도 메뉴 항목이며, 각 보고서는 **하루에 한 번만 가져옵니다**. `reports/inventory/`에 오늘 파일이 이미 있으면 그대로 사용하고 셀러 센트럴에 들어가지 않습니다.
셀러 센트럴에 오늘 생성된 같은 보고서가 있으면 다시 요청하지 않고 바로 다운로드합니다. 오늘 이미 요청해 대기 중인 보고서가 있으면 그 보고서만 기다립니다.
보고서 생성에는 최대 45분이 걸릴 수 있습니다. 기다리는 동안 2~3분(무작위)마다 페이지를 새로고침해 완료 여부를 확인하며, 창에 현재 상태, 대기 시간, 다음 새로고침 시간을 표시합니다. 간격은 `sc_reports.py` 맨 위에서 수정할 수 있습니다.
오늘 다시 가져오고 싶으면 해당 날짜의 파일을 삭제한 뒤 실행하세요.

**전체 상품 재고**: 메뉴 상품 → 상품 보고서에서 All Listings Report를 요청하고 다운로드합니다.
- `all_listings_날짜.xlsx`: 전체 상품 데이터
- `listings_report_날짜.xlsx`: 평가 요약, 확인 필요(Inactive, Incomplete, 판매자 배송 재고 없음, 가격 누락), 전체 목록, 원본 데이터

**FBA 재고**: 메뉴 공급망 → 공급망 보고서 → FBA inventory reports에서 왼쪽 Inventory(필요하면 Show more... 클릭)의
FBA Inventory 보고서(없으면 Manage FBA Inventory)를 열어 다운로드를 요청합니다.
- `fba_inventory_날짜.xlsx`: FBA 재고 데이터
- `fba_report_날짜.xlsx`: 평가 요약(판매 가능, 입고 중, 예약, 판매 불가, 최근 30일 판매량, 재고 가치, 보관료),
  확인 필요(품절, 재고 부족, 재입고 필요, 장기 미판매, 재고 기간 김, 판매 불가, 아마존 제안), 전체 목록, 원본 데이터
- 오늘 “전체 상품 재고”를 이미 실행했다면 **FBA 재고는 있는데 상품이 판매 불가**인 SKU도 확인합니다(높은 우선순위).

기타 파일: `raw/`는 아마존에서 다운로드한 원본 파일, `debug/`는 어느 단계에서 예상한 내용을 찾지 못했을 때의 스크린샷과 페이지 텍스트입니다.
평가 임계값(판매 가능 일수 14 / 30일 등)은 `inventory.py` 맨 위에서 수정할 수 있습니다.

## 주문 보고서

메뉴에서 “주문 보고서”를 선택한 뒤 기간을 고릅니다: 1 전날, 2 최근 7일, 3 최근 14일, 4 최근 30일. 메뉴에 기간별 마지막 실행 시간이 표시됩니다.

- **날짜는 미국 중부 시간 기준**: 이번 기간 = 중부 시간 어제까지 N일. 전날, 7일, 14일은 같은 길이의 이전 기간과 비교합니다(전날은 그 전날과 비교).
  30일은 이전 기간 데이터가 없어 비교하지 않습니다. 주문 시간도 UTC에서 중부 시간으로 바꾼 뒤 날짜별로 집계합니다.
- **하루에 한 번만 가져옴**: 셀러 센트럴의 날짜는 프리셋 범위만 선택할 수 있고 최대 30일이므로, 하루에 한 번 “Last 30 days”만 요청하고
  네 가지 옵션이 이 데이터를 함께 사용합니다. 다른 기간을 선택해도 다시 가져오지 않습니다. 목록에 해당 기간을 포함하는 보고서가 있으면 바로 다운로드합니다.
- 데이터 출처: 주문은 메뉴 주문 → 주문 보고서 → All Orders(Event Date에서 Date range: Last 30 days 선택 → Request),
  반품은 보고서 센터 Customer Concessions → FBA customer returns → Download 탭(Last 30 days → Request .txt Download).
  2~3분마다 새로고침해 생성 완료를 확인합니다. 반품 보고서를 가져오지 못해도 다른 내용에는 영향이 없고, 반품률만 계산하지 않습니다.
- Amazon.com(미국) 주문만 집계하며, 보고서의 다른 마켓플레이스(예: 멕시코) 주문은 제외하고 그 사실을 표시합니다.

생성되는 `reports/orders/orders_report_기간_날짜.xlsx`:
- “요약”: 주문 수, 판매 수량, 매출, 객단가, 취소율, 반품률 등 이번 기간 / 이전 기간 비교와 요점
- “일별 추이”: 날짜별 주문, 수량, 매출을 이번 기간과 이전 기간으로 비교, 추이 차트 2개
- “SKU 순위”: 이번 기간 수량순 정렬, 이전 기간 대비 수량과 매출 증감
- “취소 및 반품”, “반품 상세”: 취소율, 반품률이 높은 SKU
- “FBM 미발송”: 아직 발송하지 않은 판매자 배송 주문, 처리 기간 기준으로 기한 초과 / 기한 임박 표시
- “지역 분포”: 주별 수량, 매출, 비중, 상위 15개 주 차트
- “주문 상세”: 모든 주문 행(중부 시간으로 변환됨)

처리 기간, 취소율 / 반품률 알림 임계값은 `orders.py` 맨 위에서 수정할 수 있습니다.

## 비즈니스 보고서

메뉴에서 “비즈니스 보고서”를 선택한 뒤 기간을 고릅니다: 1 전날, 2 최근 7일, 3 최근 14일, 4 최근 30일(미국 중부 시간, 어제까지).
네 가지 모두 같은 길이의 이전 기간과 비교합니다(비즈니스 보고서는 최근 2년 데이터를 조회할 수 있음).

- 먼저 메뉴 마케팅 → 워크스페이스를 열어 페이지에서 확인할 수 있는 내용을 읽습니다: 전환율 카드(주문 매출, 세션 수, 주문 상품당 평균 매출),
  상단 지표, 프로모션, 고객 세그먼트, 인기 검색어. 워크스페이스는 하루에 한 번만 읽습니다.
- 그다음 비즈니스 보고서에서 “Detail Page Sales and Traffic By Child Item”을 열고, Date에서 Custom 선택 → 시작 / 종료 날짜 입력 → Apply,
  표가 나타나면 Download (.csv)를 클릭합니다. 이번 기간과 이전 기간을 각각 한 번씩 다운로드합니다.
  같은 기간은 한 번만 다운로드합니다(`business_data_시작_종료.xlsx`가 있으면 그대로 사용). 최근 3일이 포함된 기간은 아마존이 아직 업데이트 중이므로 다운로드한 날짜별로 따로 저장합니다.

생성되는 `reports/business/business_report_기간_날짜.xlsx`:
- “요약”: 세션 수, 페이지뷰, 주문 수량, 주문 매출, 전환율, 바이박스 비율의 이번 기간 / 이전 기간 비교, 요점, 마케팅 워크스페이스 내용
- “트래픽↑전환↓”: 세션 수가 상위 25%이고 전환율이 전체 평균의 절반 미만인 ASIN(가격, 이미지, 리뷰, 상세 설명 확인)
- “전환↑트래픽↓”: 전환율이 전체 평균의 1.5배 이상이고 세션 수가 많지 않은 ASIN(광고 추가, 키워드 최적화에 적합)
- “바이박스 90% 미만”: 바이박스 비율이 90% 미만인 ASIN
- “크게 하락”: 세션 수 또는 전환율이 이전 기간보다 30% 이상 하락한 ASIN(별도 알림)
- “ASIN 전체”: 모든 ASIN의 이번 기간 / 이전 기간 비교, 세션 수 상위 15개 차트
- “인기 검색어”: 워크스페이스의 Top Search Queries

판단 임계값은 `business.py` 맨 위에서 수정할 수 있습니다. 처음 실행하면 워크스페이스와 비즈니스 보고서 페이지 구조를 `reports/business/debug/`에 저장합니다.
읽지 못한 내용이 있으면 이 폴더의 파일을 개발자에게 보내 주시면 조정합니다.

## 광고 데이터 수집·조치 제안 (광고 Agent 1단계)

메뉴 “광고 데이터 수집·조치 제안”. **자료 수집과 제안만 하고, 광고 설정(입찰가, 키워드, 예산 등)은 바꾸지 않습니다.**
날짜는 미국 태평양 시간 기준이며 전날과 최근 7일을 정리합니다(입찰·부정 키워드 규칙은 규격서대로 최근 3일을 뺀 14일 데이터로 판단).

진행 순서(보고서 생성 시간이 일정하지 않은 문제에 대한 대책 포함):
1. Ads console → Reporting에서 필요한 보고서를 먼저 요청합니다: SP 검색어 / 타겟팅 / 캠페인 / 광고 상품, SB 검색어(최근 30일, 일별).
   처음 한 번은 “매일 자동 실행”으로 만들어 두므로, 다음 날부터는 열었을 때 이미 생성되어 있어 기다리지 않습니다.

## SP-API(Amazon 공식 API) — API 우선, 실패하면 브라우저

화면 프로그램 오른쪽 위 **⚙ 설정(API·메일)** → SP-API 탭에서 LWA Client ID · Client Secret · Refresh Token · Seller ID · 브랜드 이름을 넣고 **연결 테스트 → 저장**.
판매자 정보(Seller ID · 확인 메일 · 브랜드 이름)는 코드에 넣지 않고 이 설정에만 저장합니다. 비어 있으면 화면 위쪽에 ‘설정 필요’가 표시됩니다.
비밀값은 Windows 계정으로 암호화해 `%LOCALAPPDATA%\AmazonAIProject\sp_api.json`에만 저장(OneDrive 밖). 같은 창에서 **확인 메일**(광고 보고서 Send to)도 바꿀 수 있습니다.

API로 먼저 가져오고, 설정이 없거나 실패하면 자동으로 원래 방식(브라우저)으로 진행합니다(조회·보고서 요청만, 수정 없음):
| 기능 | API |
|---|---|
| 전체 상품 재고 / Listing 점검의 All Listings | Reports `GET_MERCHANT_LISTINGS_ALL_DATA` |
| FBA 재고 | Reports `GET_FBA_INVENTORY_PLANNING_DATA`(안 되면 `GET_FBA_MYI_UNSUPPRESSED_INVENTORY_DATA`) |
| 주문 / 반품 | Reports `GET_FLAT_FILE_ALL_ORDERS_DATA_BY_ORDER_DATE_GENERAL` / `GET_FBA_FULFILLMENT_CUSTOMER_RETURNS_DATA` |
| 비즈니스 보고서 | Reports `GET_SALES_AND_TRAFFIC_REPORT`(하위 ASIN) |
| Brand Analytics SCP · SQP | Reports `GET_BRAND_ANALYTICS_SEARCH_CATALOG_PERFORMANCE_REPORT` · `..._SEARCH_QUERY_PERFORMANCE_REPORT`(SQP는 노출 상위 ASIN 최대 90개를 나눠 요청해 검색어별로 합침) |
| 계정 상태의 클레임 | Reports `GET_V2_SELLER_PERFORMANCE_REPORT`(ODR·A-to-z·차지백·배송 지연·정책 위반 등) |
| Listing 점검의 불릿·검색어·Item Highlights | Listings Items API + **Amazon 지적 사항(issues)**, 리뷰 불만 주제(Customer Feedback API) |
| (새 기능) Amazon 할 일 | Action Items API — 메뉴 ‘Amazon 할 일 확인(SP-API)’, 매일 실행에도 포함 |

API가 없어 계속 브라우저로 하는 것: Top Search Terms, FBA 대시보드(보관 기간 비율·IPI), 입고 배송 화면, 반품 분석·VoC·브랜드 노출 점유율 화면, 상품 상세 페이지(이미지·A+), 마케팅 워크스페이스.

## 리스팅·가격 수정(SP-API) — 2단계, 확인한 것만 적용

화면 프로그램 왼쪽 ‘수정(확인 후 적용)’ → **리스팅·가격 수정(SP-API)** 를 실행하면 수정 창이 열립니다.
1. **① 빈 요청서 만들기** → `reports/changes/변경_요청서.xlsx`(머리글·항목 선택 목록·안내만, 바로 만들어짐).
   초안이 필요하면 **초안 채운 요청서** → Listing 점검의 제목·Item Highlights 초안 + ‘현재 가격표’ 시트(SP-API, 1~3분). 적용 칸은 비어 있음
2. 바꿀 줄에 `적용(Y)`=Y, `항목`(제목·가격·불릿1~5·검색어·설명·하이라이트=Item Highlights), `새 값`을 적고 저장
3. **② 검사** — 현재 값을 읽고 Amazon VALIDATION_PREVIEW로 오류만 확인(실제 변경 없음). 초록=적용 가능, 주황=큰 가격 변경, 빨강=오류
4. 적용할 줄을 고르고(‘적용’ 칸 클릭) **③ 선택한 줄 적용** → 확인 창 → Amazon에 반영(보통 몇 분~몇 시간)
5. 모든 변경은 `변경_기록.xlsx`·`change_log.json`에 원래 값과 함께 기록, **변경 기록·반영 확인**에서 원래 값으로 되돌림
   가격 줄은 **가격 변경 시 수수료·이익** 칸에 새 가격의 Amazon 수수료(판매 수수료·FBA, Product Fees API)와 1개당 남는 금액을 보여 줌.
   `reports/ads/ads_config.xlsx` ‘ASIN 원가’에 원가를 넣으면 이익·이익률·지금 가격 대비 변화까지, 손해 가격이면 ‘큰 변경’처럼 따로 허용해야 적용
6. API의 ‘접수됨(ACCEPTED)’은 Amazon이 받았다는 뜻일 뿐, 실제 반영은 몇 분~몇 시간 뒤입니다. **반영 확인**을 누르면 현재 값을 다시 읽어 상태를 표시:
   | 상태 | 뜻 |
   |---|---|
   | 접수됨 | 적용 직후(아직 확인 안 함) |
   | 처리 중 | 아직 이전 값(적용 후 24시간 이내) |
   | 제출값 저장됨 | 내 리스팅(제출값)에는 저장됐지만 고객에게 보이는 값은 아직 이전 값(보통 15분~몇 시간) |
   | 반영됨 | 고객에게 보이는 값 = 새 값: 제목·불릿·설명·하이라이트는 카탈로그(Catalog Items API, 상세 페이지 내용), 가격은 판매 중 오퍼 가격으로 확인. 검색어는 고객에게 안 보여 제출값 기준(‘확인 기준’ 칸) |
   | 반영 안 됨 | Amazon 오류(issue), 24시간이 지나도 제출값이 다름, 또는 제출값은 저장됐지만 48시간이 지나도 카탈로그가 다름(브랜드 소유자 등 다른 기여 우선) — 메시지에 이유 |
   | 되돌림 / 이후 변경으로 대체 | 되돌렸거나 같은 항목을 다시 바꿈 |
   기록에는 적용 시각·반영 확인 시각·마지막 확인·Amazon 마지막 업데이트가 남고, 매일 자동 실행 때 자동으로 확인합니다
   (반영 안 됨 → 오늘의 요약 P2, 6시간 넘게 처리 중 → P3).

안전 장치: 가격 0 이하 금지, 현재 가격 ±30% 초과는 ‘큰 변경 허용’을 체크해야 적용, 최소/최대 허용 가격 밖이면 주의 표시,
제목 200자 초과 금지·75자 초과·금지 문자 주의, 한 번에 최대 50건, 적용한 줄은 요청서에서 ‘완료’로 바뀌어 두 번 적용되지 않음.
같은 SKU의 불릿 여러 개처럼 같은 속성을 여러 줄 바꾸면 앞 줄 변경을 포함해 이어서 반영합니다.
필요 권한: 개발자 앱의 **Product Listing** 역할(‘전체 점검’의 ‘리스팅 수정’·‘가격 수정’ 줄로 확인).

## Amazon Ads API(광고 보고서) — API 우선, 실패하면 광고 콘솔 화면

‘⚙ 설정’ → **Amazon Ads API** 탭(처음 한 번):
1. Ads 앱의 LWA **Client ID · Client Secret** 입력, **Redirect URI**는 LWA 보안 프로필의 *Allowed Return URLs*에 등록한 주소와 똑같이(기본 `https://amazon.com`)
2. **① 인증 페이지 열기** → Amazon 로그인 → Allow → 이동한 페이지의 **주소창 전체**를 복사해 붙여 넣고 **② 토큰 받기**(code는 몇 분 안에 한 번만 사용 가능)
3. 프로필이 자동으로 골라짐(미국 판매자). 다르면 목록에서 선택 → **연결 테스트 → 저장**

광고 기능을 실행하면 v3 보고서(최근 30일·하루 단위)를 API로 받아 기존과 같은 파일 `reports/ads/data/날짜/rp_*.xlsx`로 저장합니다(조회만, 입찰·예산·키워드는 바꾸지 않음):
| 파일 | Ads API 보고서 |
|---|---|
| rp_sp_search_term | `spSearchTerm` + 스폰서드 브랜드 `sbSearchTerm`(있으면 합침) |
| rp_sp_targeting | `spTargeting` |
| rp_sp_campaign | `spCampaigns`(캠페인 + 게재 위치) |
| rp_sp_advertised_product | `spAdvertisedProduct` |
열 구성이 맞지 않으면 기본 열로 다시 요청하고, 그래도 안 되거나 설정이 없으면 원래대로 광고 콘솔 Reporting 화면에서 받습니다.
API로 모두 받으면 광고 콘솔 화면에서는 보고서를 요청하지 않습니다(브랜드 노출 점유율·광고 추천·Brand Analytics·Top Search Terms는 계속 화면에서).
원본: `reports/api_raw/ads_*.json`.

## 운영 편의 기능

- **Excel 수식 주입 방지**: 보고서에 들어가는 Amazon 글자(고객 검색어·상품명 등)가 ‘=’로 시작해도 수식으로 실행되지 않고 글자로 저장됩니다(이 프로그램이 만드는 단순 계산식만 수식).

- **API 전체 점검**: ‘⚙ 설정(API·메일)’ → **전체 점검** — 인증·각 보고서·리스팅·할 일·리뷰 API와 **리스팅·가격 수정 권한**(현재 값 그대로 VALIDATION_PREVIEW로 검사만, 실제 변경 없음)을 가장 작은 요청으로 확인하고 ✅/❌와 원인(권한·Seller ID 등)을 보여 줌
- **동시 실행 방지**: 다른 작업(예약 실행 포함)이 브라우저를 쓰는 중이면 끝날 때까지 기다렸다가 자동 시작(최대 3시간, 매일 실행은 4시간)
- **자동 정리**(하루 한 번): debug 14일, 로그·API/다운로드 원본 30일 지난 것 삭제, 예전 메뉴 스캔·탐색 결과는 최근 2번만 보관(보고서 Excel은 지우지 않음)
- **오늘의 요약**: ‘데이터 출처’(API / 브라우저 / API 실패 후 브라우저) 시트와 API 실패 알림, **30일 추세** 시트(매일 기록되는 숫자 지표 + 주요 그래프)
- **재입고 제안**(FBA 재고 보고서 ‘보충 제안’ 시트): 하루 판매량(30일 60% + 90일 40%)·리드타임·안전 재고·목표 보유 일수로 보낼 수량과 날짜 계산.
  설정은 `reports/inventory/restock_config.xlsx`(기본값 45 / 14 / 60일, SKU별 변경·제외 가능)
- **Windows 알림**: 매일 자동 실행(예약)이 끝나면 P0·P1 건수와 가장 급한 일 1건을 알림으로 보여 주고, 누르면 요약 Excel이 열림.
  화면 프로그램이 뒤에 있거나 최소화돼 있을 때 기능이 끝나도 알림. ‘⚙ 설정 → 메일·알림·토큰 교체’에서 끄기·시험
- **토큰 교체**: 설정 화면에 각 Refresh Token 저장일이 표시되고, 기록이 없거나 180일이 지나면 오늘의 요약에 P3 알림. 교체 방법은 같은 탭에 안내
- **제목 초안**(Listing 점검 ‘제목 초안’ 시트): 75자 넘는 제목의 75자 초안 + Item Highlights(125자) 초안 + 초안에서 빠진 인기 검색어. 자동 적용하지 않음

## 화면 프로그램(Windows 10 / 11)

`start_gui.bat`를 더블클릭하면 창으로 된 프로그램이 열립니다(처음 한 번 ‘바탕화면 바로가기 만들기’를 누르면 다음부터 바탕화면에서 실행).
- **왼쪽**: 모든 기능 목록. 이름을 누르면 설명·마지막 실행·옵션(주문/비즈니스 기간, 매일 실행 설정·자동 실행 예약)이 보이고, **▶ 이 기능 실행**(또는 이름 더블클릭).
  여러 기능을 체크하고 **▶ 체크한 기능 차례로**를 누르면 순서대로 실행합니다. **■ 중지**로 언제든 멈춤(브라우저도 닫힘).
- **오른쪽 위 실행 로그**: 진행 상황이 실시간으로 표시됩니다(오류 빨강·경고 주황·완료 초록). 실행할 때마다 `reports/logs/`에 로그 파일로도 저장.
- **오늘의 요약 탭**(실행 로그 옆): 오늘 P0~P3 건수, 홈 화면 수치, 오늘 실행한 기능 성공/실패, 조치 목록(P0·P1만 / 전체). 줄을 더블클릭하면 그 기능의 결과 파일이 열림.
  ‘요약 다시 만들기’, ‘요약 Excel 열기’. 기능이 끝날 때마다 자동으로 새로 고침
- **결과 파일**: 방금 만든 파일 열기 / 위치 열기, 아래 목록에서 최근 결과 파일을 더블클릭으로 열기·폴더에서 보기·기능별 결과 폴더 열기.
- 기능은 별도 프로세스(`runner.py`)에서 실행되어 화면이 멈추지 않습니다. 한 번에 하나만 실행됩니다(같은 로그인 프로필 사용).
- 기존 콘솔 메뉴(`start.bat`)도 그대로 쓸 수 있습니다.
- 창이 열리지 않으면 `python app\gui.py`로 실행해 오류를 확인하세요(Python 설치 시 ‘tcl/tk and IDLE’ 항목이 필요, 기본 설치에 포함).

## 매일 자동 실행 · 오늘의 요약

시간 줄이기: 첫 브라우저 기능(홈 화면)이 끝나면 **광고 보고서를 미리 요청**해 두고(생성에 20~40분), 광고 단계에서는 받기만 합니다. 전체 상품 보고서·Brand Analytics 파일은 그날 한 번 받아 여러 기능이 같이 씀. 끝나면 기능별 걸린 시간을 로그·오늘의 요약(화면 탭)에 표시.

2. **오늘의 요약**: `reports/daily/daily_summary_날짜.xlsx` — 홈 화면 수치(오늘 매출·판매 중 상품·IPI·미처리 주문·순수익·광고 7일), 오늘 처리할 일(P0·P1, 같은 종류는 한 줄로 묶음), 실행 결과, 조치 필요 전체, 기능별 수치

## 주의 사항

- 프로그램은 PC의 Chrome 프로그램을 사용하지만 로그인 데이터는 별도 폴더에 저장하므로, 평소 사용하는 Chrome 설정, 북마크, 확장 프로그램은 건드리지 않습니다. 그래서 처음 한 번은 열린 창에서 다시 로그인해야 합니다.
- 로그인 데이터는 `%LOCALAPPDATA%\AmazonAIProject\browser_profile`(이 PC, OneDrive 밖)에 저장됩니다. 프로젝트 폴더는 OneDrive에서 동기화되므로, 로그인 데이터를 프로젝트 안에 두면 쿠키가 클라우드에 올라가고 실행 중인 Chrome 설정이 동기화 때문에 손상될 수도 있습니다. 위치를 바꾸려면 환경 변수 `SC_PROFILE_DIR`을 설정하세요.
- 이 폴더에는 로그인 쿠키가 들어 있어 계정 자격 증명과 같습니다. 공유하거나 Git, 클라우드 드라이브에 올리지 마세요.
- 평소 사용하는 이 PC와 네트워크에서만 실행하고, 클라우드 서버로 옮겨 사용하지 마세요.
- 한 번에 하나의 스크립트만 실행하세요. 두 스크립트가 같은 로그인 데이터를 동시에 열면 오류가 납니다.
- 프로그램은 비밀번호를 저장하지 않습니다. 세션이 만료되면(보통 며칠~몇 주) 다시 한 번 직접 로그인하면 됩니다.
- 우선 읽기 작업만 하고, 가격 변경, 광고 변경 같은 쓰기 작업은 사람이 확인하는 단계를 두는 것을 권장합니다.

### 버전별 패키지(releases 폴더)

`release.bat`(Mac: `release.command`)을 더블클릭:

- **1 만들기** → `releases/SellerMorning_v버전_날짜.zip`. 프로그램 파일(app/, 실행 파일, README 등)만 넣고 `reports`(판매 데이터)·`__pycache__`·정리용 bat은 넣지 않음. 로그인 정보·API 키·Seller ID는 원래 프로젝트 밖에 있어 들어가지 않으며, 만들기 전에 설정 값이 파일에 들어 있는지 검사(있으면 만들지 않음).
  패키지 안 `RELEASE.txt`에 파일마다 크기·SHA-256 기록. 같은 버전 패키지가 있는데 파일이 바뀌었으면 만들지 않고 `app/version.py`에서 버전을 올리라고 안내.
- **2 목록**
- **3 되돌리기**: 버전을 입력하면 그 패키지로 프로그램 파일을 바꿈(먼저 지금 파일을 `releases/backup/`에 묶어 둠, 패키지 손상 검사). reports·설정·로그인은 그대로.

버전 번호는 `MAJOR.MINOR.PATCH`(유의적 버전)입니다. 현재 버전은 `app/version.py`에 있고, 화면 프로그램 제목·위쪽 막대, 메뉴(start.bat), 실행 로그 첫 줄, 오늘의 요약에 표시됩니다.

| 자리 | 올리는 경우 | 예 |
|---|---|---|
| MAJOR | 예전 설정·자료와 맞지 않게 바뀔 때(설정을 다시 하거나 자료 형식이 바뀜) | 1.4.2 → 2.0.0 |
| MINOR | 새 기능을 더할 때(예전 것은 그대로 동작) | 1.4.2 → 1.5.0 |
| PATCH | 고치기만 할 때(오류 수정·문구·작은 개선) | 1.4.2 → 1.4.3 |

| 버전 | 날짜 | 내용 |
